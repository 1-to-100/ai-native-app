# Skills — inventory

Read this before executing anything. Each skill below is a deterministic procedure with declared inputs, the files it reads, the files it writes, and the point at which it stops. Invoke a skill by name rather than improvising the procedure. If no skill covers a task, perform it under `AGENTS.md` and the governing format, then run `improve-process` if the task recurs often enough to become a skill.

## Shared rules

- **Client slug prompting.** Any skill that takes a client slug and is not given one lists the folders under `clients/` and asks the operator to pick one. It never guesses.
- **Operator email.** Every governed data file a skill writes carries the human operator's email in `created_by` and `updated_by`. Ask once per session if it is not known.
- **Format first.** A skill reads the governing format before writing or editing any document. `python3 scripts/check.py` runs before the skill reports done.
- **No invention.** Facts, metrics, quotes, reasons to believe, client reactions, and commercial terms are written only from a source or left `None` with an open issue when the gap is about a client.
- **Interstitial files in `tmp/`.** Working files, proposals, and setup reports are written under `tmp/` and never committed. An `upgrade-app` plan is the exception and goes in `docs/upgrades/`.
- **Stopping points are real.** A skill stops where its entry says, reports what it completed and what remains open, and leaves the next step to the operator.

## Adding a skill

Create `.agents/skills/<skill-name>/SKILL.md` with YAML front matter (`name` and `description`), then the sections `## When to use`, `## Inputs`, `## Reads`, `## Procedure`, `## Writes`, `## Stops when`, and `## Never`. Add a row to the table above in the same commit. Then run `python3 scripts/setup-scripts.py` to wire the skill for the target AI environment.
